# LolkaMod 0.3.0

LolkaMod — экспериментальная модификация клиента Lolka для Windows x64. Исходники: [Bnmrnzxc/LolkaMod](https://github.com/Bnmrnzxc/LolkaMod).

**[Скачать установщик 0.3.0](https://github.com/Bnmrnzxc/LolkaMod/releases/download/v0.3.0/LolkaModInstaller-0.3.0.exe)** · [Все файлы релиза](https://github.com/Bnmrnzxc/LolkaMod/releases/tag/v0.3.0)

Поддерживается только **Lolka 1.0.120** с исходным `resources/app.asar`, SHA-256:

```text
fd94ecec264d7d7a56a0b5d1bb5ac1e416b6c9a4ee2d171b3704b0b72f0260a8
```

Установщик собран для Windows x64 и .NET Framework 4.8; для установки готового EXE Node.js не нужен. Полностью закройте Lolka, включая значок в системном трее, запустите установщик и нажмите «Установить / обновить». Папка клиента выбирается автоматически; её можно изменить. Обновление существующей установки мода сохраняет оригинальный архив и настройки.

Поддерживаемый renderer hash `ENTRY_HASH` находится в [source adapter](src/main/source-adapter.ts). Для неизвестного renderer bundle внутренние патчи пропускаются и загружается исходный ответ. Диагностика остаётся доступной, но разблокировка качества требует совместимого адаптера.

## Управление

После установки штатный выбор качества демонстрации экрана получает разрешения **720p, 1080p и 1440p**, а также **30 и 60 FPS**. Выбор остаётся в обычном меню Lolka, и активное значение этого меню синхронизируется с модом. Параметры сохраняются в обычных `localStorage` настройках клиента и переживают перезапуск. Отдельная кнопка LM и отдельный профиль качества не нужны; legacy-поля качества из LolkaMod 0.2 игнорируются.

Для CSS-настройки и диагностики нажмите **Ctrl+Shift+M**. В панели можно открыть Custom CSS и диагностический снимок. CSS и диагностика не нужны для выбора качества в штатном меню; исходный режим по умолчанию определяется клиентом.

Установщик приостанавливает автообновления Lolka, пока активен shim LolkaMod. Перед обычным обновлением удалите мод через установщик, чтобы восстановить исходный `app.asar`; настройки и профиль пользователя сохраняются. Параметр запуска `--lolkamod-disable` запускает оригинальный main на этот запуск; оригинальный updater в этом режиме может обновить Lolka, поэтому поддержку новой версии нужно проверять отдельно.

Установщик также поддерживает headless-операции `--install`, `--status`, `--uninstall` и `--repair` с путём клиента и JSON-отчётом через `--report`. Тестовый путь профиля передаётся только с `--install --test-user-data <отдельная-папка>`.

## Экспериментальное качество стрима

Мод использует штатный picker и связанные с демонстрацией capture/WebRTC пути. Цели в меню задают запрашиваемые разрешение и частоту кадров, но не гарантируют такой же размер у зрителя или стабильную частоту кадров: на результат влияют источник, браузер, сеть и принимающий сервер. Для проверки 1440p нужен реальный источник не меньше 2560×1440; мод не увеличивает источник 1080p.

55 локальных тестов прошли. Проверка штатного React picker прошла последовательность 1440p/60 → 720p/30 → 1080p/30 → 1440p/60, повторное открытие и полный перезапуск. Локальный WebRTC подтвердил capture/encoded/decoded 2560×1440 при выбранных лимитах 60 FPS; измеренный FPS был ниже 60. Реальные OS capture, audio, SFU и стабильные 1440p/FPS пока не подтверждены. Инструкция по сбору метрик — в [руководстве по проверке стрима](docs/stream-test.md).

## Устройство и происхождение подхода

Модификация использует девять атомарных патчей и Vite ESM adapter при точном совпадении поддерживаемого renderer bundle. У [Vencord FakeNitro](https://github.com/Vendicated/Vencord/blob/main/src/plugins/fakeNitro/index.tsx) изучен принцип изменения локальных проверок доступности штатных режимов стрима. Для Lolka он реализован самостоятельно в её меню и медиапути. LolkaMod — независимый MIT-проект; исходный код Vencord не копировался. Подробности — в [архитектуре](docs/architecture.md).

## Сборка и разработка

Для разработки нужен Node.js **22.12 или новее**.

```powershell
npm ci
npm run build
npm run typecheck
npm test
npm run build:installer
```

`npm run fetch:frontend` — необязательная операция. Она получает публичный frontend fixture и сохраняет его только при совпадении с `ENTRY_HASH` source adapter. Fixture в `research/public-frontend/` предназначен для разработки и тестов и не входит в установщик.

На Windows с готовой нативной сборкой запускаются headless-тесты установщика. Если Windows EXE или оригинальный ASAR fixture отсутствуют, эти тесты помечаются `SKIP`. Полный vendor-клиент и профиль пользователя в репозитории не хранятся. Автоматические тесты продолжают расширяться; их текущий результат не подтверждает реальный SFU-путь.
