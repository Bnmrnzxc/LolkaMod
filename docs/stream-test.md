# Проверка качества стрима

Руководство для ручной проверки LolkaMod 0.5.0. Выбор разрешения и FPS делается в штатном меню демонстрации экрана Lolka. Индикатор включается в разделе LolkaMod. Резервная панель диагностики открывается клавишами **Ctrl+Shift+M**; отдельная кнопка LM или профиль Stream Quality не используются.

## Перед тестом

- Используйте Windows x64 и совместимую Lolka. Проверенная исходная версия — 1.0.120; статус патчей интерфейса доступен в диагностике.
- Установите совместимую сборку мода у отправителя. Для inbound WebRTC stats зрителю тоже нужна совместимая сборка: отправитель не может показать decoder stats удалённого клиента.
- Полностью закройте клиент во время установки или обновления, включая значок в системном трее.
- Для 1440p подготовьте реальный экранный источник не меньше 2560×1440. Захват окна с изображением 1080p не становится 1440p от выбора большего режима.
- Согласуйте тестовую сцену и сеть. Используйте динамичное содержимое с мелкими деталями; статичная картинка не подходит для оценки FPS.

## Отправитель

1. Начните демонстрацию экрана штатным способом.
2. В обычном меню выбора качества установите **1440p** и **30 FPS**. Это запрошенные параметры; они не являются фактическим измерением.
3. Откройте диагностику через **Ctrl+Shift+M** и обновите снимок после начала передачи.
4. Запишите `capture`, `encoded`, `codec`, `bitrateKbps`, `qualityLimitationReason` и `packetLossCount` для исходящего video.

`capture` показывает параметры захваченного video track; frameRate здесь — настройка захвата, а не измеренная частота кадров. `encoded` описывает отправленные кадры. Для реального 1440p ожидаются ширина и высота 2560×1440 и у захвата, и у encoded кадров. Фактический FPS считывайте из метрик, а не из выбранного значения меню.

## Зритель

Попросите собеседника подключиться к той же демонстрации, открыть **Ctrl+Shift+M** и записать `decoded`, `codec`, `bitrateKbps`, `packetLossCount` и `qualityLimitationReason` для inbound video, если эти поля доступны.

Inbound media может быть помечена `unknown`: классификация не выводит тип входящего видео из идентификаторов. Сопоставляйте запись с единственной активной демонстрацией и не добавляйте в отчёт пользовательские ID, URL или сетевые данные.

## Повторы

1. В штатном меню выберите 720p/30, остановите и начните демонстрацию, затем сохраните диагностический снимок.
2. Повторите для 1080p/30 и 1440p/60. Перезапустите демонстрацию между режимами.
3. Для проверки перезапуска закройте и откройте клиент. До нового выбора проверьте, что штатное меню показывает сохранённый режим.
4. Повторите после переподключения к сеансу. Зафиксируйте stop/start и reconnect как отдельные прогоны.

Сделайте снимки отправителя и зрителя для каждого прогона. Перед передачей материалов уберите имена, личные окна, приглашения, URL, токены и другие пользовательские данные.

## Что считать подтверждением

Результат **1440p30 у отправителя и зрителя** подтверждается только при наблюдаемых `capture` и `encoded` 2560×1440 у отправителя, `decoded` 2560×1440 у зрителя и фактической частоте кадров около 30 с обеих сторон в нескольких прогонах. Для 1440p60 нужен отдельный динамичный прогон с наблюдаемыми кадрами около 60. Настройка меню, preview и одиночный снимок не подтверждают стабильность. Скорость `bitrateKbps` вычисляется по приросту RTP byte counters и времени; учитывайте колебания, потери и `qualityLimitationReason`.

Уже прошла проверка штатного React picker: **1440p/60 → 720p/30 → 1080p/30 → 1440p/60**, включая remount и полный restart. Локальный canvas/WebRTC подтвердил capture/encoded/decoded 2560×1440. Лимиты были 60 FPS; измеренный FPS в коротком прогоне составил 31 у отправителя и 36 у получателя. Это не подтверждает стабильные 60 FPS, захват экрана ОС или передачу через реальный SFU.

Реальный OS capture и capture audio, SFU-передача, viewer на 1440p и стабильный FPS пока не подтверждены. Для проверки потребуется реальный сеанс с собеседником; не считайте приведённые ниже примерные значения результатом измерений.

### Синтетический пример формата — выдуманные данные

```json
{
  "media": "screen",
  "direction": "outbound",
  "capture": { "width": 2560, "height": 1440, "fps": 30 },
  "encoded": { "width": 2560, "height": 1440, "fps": 30 },
  "decoded": null,
  "codec": "VP8",
  "bitrateKbps": 12100,
  "packetLossCount": 0,
  "qualityLimitationReason": "none"
}
```

## Запись прогона

```text
Дата / Lolka / LolkaMod / ОС:
Отправитель: штатный режим / исходный источник и разрешение
Отправитель: capture / encoded / codec / bitrateKbps / FPS / packet loss / limitation
Зритель: decoded / codec / bitrateKbps / FPS / packet loss / limitation
Повторы: stop/start / перезапуск / reconnect / число прогонов
Свидетельства: пути скриншотов или очищенный от приватных данных экспорт
Ограничения и результат: 1440p30 или 1440p60 подтверждено / не подтверждено
```
