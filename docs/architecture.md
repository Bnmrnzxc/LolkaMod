# Устройство LolkaMod

Установщик сохраняет оригинальный ASAR, размещает shim и запускает оригинальный main через внешний `main.cjs`. Оригинальный preload берётся из установленного клиента и включается в отдельной области видимости до preload мода. Распространяемый EXE не содержит Lolka, Electron или оригинальный preload. Main, preload и renderer собираются отдельно; sandbox и context isolation остаются включёнными, Node.js в renderer не включается. Bridge предоставляет ограниченный доступ к настройкам, диагностике и ручной проверке публичных релизов. Произвольные пути и URL через bridge не принимаются.

## Встраивание в клиент

Внутренний source adapter изменяет поддерживаемый JS entry и добавляет reference в его lexical scope. Девять патчей применяются одной группой: списки допустимых сохранённых значений, пункты picker и активного меню, выбранные параметры browser capture/producer и screen-only encoder preference. Известный `ENTRY_HASH` использует быстрый путь. Другие сборки разбираются Acorn: сопоставление токенов переносит переименованные локальные ссылки и проверяет уникальность участков, связи компонентов, константы и медиаконтракты. Готовый ESM повторно проверяется на синтаксис. Несовместимый код загружается без патчей. [Границы совместимости](compatibility.md).

В [Vencord FakeNitro](https://github.com/Vendicated/Vencord/blob/main/src/plugins/fakeNitro/index.tsx) stream quality bypass изменяет `canStreamQuality` и требования guild premium tier в штатных FPS options. В Lolka применён тот же принцип к её локальным проверкам; глобальные premium/auth stores и серверные права не меняются. Webpack patcher заменён Vite ESM response transform. LolkaMod — самостоятельный MIT-проект; исходный код Vencord не копировался.

Пункты 720p, 1080p и 1440p вместе с 30/60 FPS используют обычные значения `localStorage` клиента. Отдельный модовый профиль не создаётся. Старые поля отдельного quality-профиля 0.2 не используются. Legacy параметр bitrate не управляет пунктами штатного меню.

## Медиа и диагностика

StreamDiagnostics запускается автоматически, наблюдает `getDisplayMedia` и новые `RTCPeerConnection`, затем читает `getStats`. Фиксированный StreamQuality engine из 0.2 не запускается: разрешение/FPS/кодек и битрейт применяет штатный клиент. Прямой browser fallback читает три штатных ключа вместо захардкоженных 720p/30. Screen producer получает `maintain-resolution`; это допускает снижение FPS при нехватке ресурсов. Camera/audio paths не получают такой патч.

В штатные настройки и toolbar добавляются независимые проверяемые группы HostSettings/StreamControls. Встроенная вкладка использует hooks и JSX runtime самого клиента; UI LolkaMod монтируется в её контейнер с cleanup. Второй React root применяется только для тестового mount на отдельной копии.

Раздел тем, индикатора, обновлений и Custom CSS доступен в настройках; резервная панель открывается сочетанием **Ctrl+Shift+M**. Она не является обязательной для выбора качества. Snapshot содержит агрегированную медиа-диагностику и не включает SDP, ICE/IP, cookies, track labels, пользовательские идентификаторы или auth payload.

Patcher и collector снимают только принадлежащие модулям hooks. Остановка мода не закрывает peer connections клиента и не останавливает host tracks. Обработчики `close`/`stop` и периодические опросы убираются при cleanup; восстановление чужих поздних замен методов не выполняется.

## Установка и эксплуатационные границы

Установщик проверяет структуру Lolka и сохраняет версию/хеш её оригинального ASAR в manifest schema 2. Повторная установка обновляет свой shim либо перепатчивает новый оригинал после vendor update, сохраняя предыдущий backup отдельно. Uninstall/repair не возвращают старую версию поверх нового совместимого оригинала. Journal и staging позволяют откатить прерванную операцию. Shim приостанавливает оригинальное автообновление; `--lolkamod-disable` позволяет разово запустить оригинальный main. Пользовательские настройки сохраняются.

Тестовая интеграция подтверждает переходы штатного picker в изолированной копии: 1440p/60 → 720p/30 → 1080p/30 → 1440p/60, включая remount и полный restart. Canvas/local WebRTC подтвердил capture/encoded/decoded 2560×1440. Реальные OS capture/audio, удалённый viewer через SFU и стабильные 60 FPS остаются непроверенными.

Магазин плагинов и dependency graph ещё не реализованы. Несущественные пересборки интерфейса могут поддерживаться автоматически; изменённые API или неоднозначные участки требуют новой версии адаптера. EXE распространяется без цифровой подписи.

Общая схема настроек 1, атомарная миграция и update service описаны в [возможностях и границах](features.md). Индикатор использует безопасный локальный ID, timestamp/age и один collector; голос и stream audio controls не изменяются.
