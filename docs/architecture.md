# Устройство LolkaMod 0.3.0

Установщик сохраняет оригинальный ASAR, размещает shim и запускает оригинальный main через внешний `main.cjs`. Оригинальный preload берётся из установленного клиента и включается в отдельной области видимости до preload мода. Распространяемый EXE не содержит Lolka, Electron или оригинальный preload. Main, preload и renderer собираются отдельно; sandbox и context isolation остаются включёнными, Node.js в renderer не включается. Bridge предоставляет ограниченный доступ к настройкам и диагностическим метаданным.

## Встраивание в клиент

Внутренний source adapter изменяет точные фрагменты поддерживаемого JS entry и добавляет reference в его lexical scope. Девять патчей применяются одной группой: списки допустимых сохранённых значений, пункты picker и активного меню, выбранные параметры browser capture/producer и screen-only encoder preference. Каждый якорь должен встретиться ровно один раз. Adapter разрешён только для совпавшего `ENTRY_HASH` из [source adapter](../src/main/source-adapter.ts); при несовпадении исходный ответ загружается без этой группы. Полный результат разбирается esbuild на точном fixture при разработке.

В [Vencord FakeNitro](https://github.com/Vendicated/Vencord/blob/main/src/plugins/fakeNitro/index.tsx) stream quality bypass изменяет `canStreamQuality` и требования guild premium tier в штатных FPS options. В Lolka применён тот же принцип к её локальным проверкам; глобальные premium/auth stores и серверные права не меняются. Webpack patcher заменён Vite ESM response transform. LolkaMod — самостоятельный MIT-проект; исходный код Vencord не копировался.

Пункты 720p, 1080p и 1440p вместе с 30/60 FPS используют обычные значения `localStorage` клиента. Отдельный модовый профиль не создаётся. Старые поля отдельного quality-профиля 0.2 не используются. Legacy параметр bitrate не управляет пунктами штатного меню.

## Медиа и диагностика

StreamDiagnostics запускается автоматически, наблюдает `getDisplayMedia` и новые `RTCPeerConnection`, затем читает `getStats`. Фиксированный StreamQuality engine из 0.2 не запускается: разрешение/FPS/кодек и битрейт применяет штатный клиент. Прямой browser fallback читает три штатных ключа вместо захардкоженных 720p/30. Screen producer получает `maintain-resolution`; это допускает снижение FPS при нехватке ресурсов. Camera/audio paths не получают такой патч.

Панель Custom CSS и диагностики открывается сочетанием **Ctrl+Shift+M**. Она не является обязательной для выбора качества. Snapshot содержит агрегированную медиа-диагностику и не включает SDP, ICE/IP, cookies, track labels, пользовательские идентификаторы или auth payload.

Patcher и collector снимают только принадлежащие модулям hooks. Остановка мода не закрывает peer connections клиента и не останавливает host tracks. Обработчики `close`/`stop` и периодические опросы убираются при cleanup; восстановление чужих поздних замен методов не выполняется.

## Установка и эксплуатационные границы

Поддерживается оригинальная Lolka 1.0.120 с точным исходным SHA-256, проверяемым установщиком. Shim приостанавливает оригинальное автообновление, чтобы изменения клиента не обошли проверку совместимости. Параметр `--lolkamod-disable` позволяет разово запустить оригинальный main; тогда updater может заменить клиент, и новую версию потребуется проверить. Удаление через установщик восстанавливает оригинальный ASAR побайтно и сохраняет пользовательские настройки.

Тестовая интеграция подтверждает переходы штатного picker в изолированной копии: 1440p/60 → 720p/30 → 1080p/30 → 1440p/60, включая remount и полный restart. Canvas/local WebRTC подтвердил capture/encoded/decoded 2560×1440. Реальные OS capture/audio, удалённый viewer через SFU и стабильные 60 FPS остаются непроверенными.

Магазин плагинов, dependency graph и автоматическая миграция renderer-патчей ещё не реализованы. Изменение публичного bundle требует нового точного hash, проверки anchors и сборки.
